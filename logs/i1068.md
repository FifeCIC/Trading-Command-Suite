# The bar refresh FABRICATES bars — 1,172 rows written while the market was shut, and they made dead feeds read as live

**Found 2026-10-03** while answering a different question (*"why is the newest 1m bar 24 minutes old?"*).
The 1m answer turned out to be "the market is closed, 20:54 Friday is the newest bar that exists" — and
the search for that answer found this.

---

## What was happening

`BarRefreshService.doRefresh()` ended with a block that:

1. called `getQuote(symbol)`,
2. took `(bid + ask) / 2`,
3. floored the **local clock** to the current 5m bucket,
4. and `INSERT`ed a bar: `provider 'mt5'`, `timeframe '5m'`, `open = high = low = close = mid`,
   **`volume 1`**, `recordingSessionId NULL`.

It ran for **every symbol** on **every refresh**, whether or not the market was open.

## The measurement

| What | Value |
|---|---|
| Rows written after Friday's close | **1,172**, across **52 symbols** |
| Rows that were flat (`o=h=l=c`) | **1,172 of 1,172** (100%) |
| Rows with `volume <= 1` | **1,172 of 1,172** (100%) |
| First / last bar | `2026-10-02 21:05` → `2026-10-03 13:50` |
| Same signature *before* the close | **55,518 rows across 67 symbols** — see "Not done" below |

The bridge's own `/candles` for the same symbol returns **nothing after Fri 20:54**. So the bars were
never market data.

## The proof, not an inference

```
GET :5000/quote?symbol=XAUUSD  →  { "bid": 4147.62, "ask": 4147.97, "timestamp": "2026-10-03T13:52:05.876Z" }
(4147.62 + 4147.97) / 2        =  4147.795
```

**`4147.795` is the exact value carried by every one of the 1,172 rows.** The writer, the arithmetic
and the output are identified, not guessed.

Distinct close prices across the flat rows: **84**, range `0.561545` (NZDUSD) → `51217` (US30) — each
symbol carries its **own** plausible price, so this was not cross-symbol contamination. It is a frozen
quote.

## Why it is dangerous — not the orphan rows, but what they claim

**The bar is stamped at the CURRENT bucket, so `MAX(timestamp)` is always ~now.**

A symbol whose feed died on Friday **measures as FRESH on Monday**. That is this repo's most expensive
failure signature: *plausible values, no error*. Every freshness and staleness check downstream reads
the affected symbol as healthy.

### ⚠️ It also silently countermanded a guard that was working

The **same refresh run** reported:

```
Bar refresh: SKIPPED 209 stale bar set(s) — every broker's newest bar was outside its cadence
tolerance. These were not written. (#838)
```

...and then this loop wrote a fresh-looking row for those same symbols. `#838` exists specifically to
stop a symbol reading as fresh when its feed is stale. Two guards, in one pass, contradicting each
other — and the newer one won silently.

The block bypassed `isStaleSet`, `alignBarTimestamp` **and** `isBarFutureStamped` — its own comment
says so: *"This one needs no future-stamp check."*

## Why the existing test suite could not see it

`bar-refresh-stale-recheck.spec.ts` builds its adapter mock with `getCandles` only, and records why:

```ts
getCandles: jest.fn(async () => primaryBars),
// No `getQuote` → the synthetic-quote loop is skipped, so it cannot add writes.
```

**The mock was shaped so the defect could not fire.** Every assertion passed while the live system
fabricated 1,172 bars. A suite that excludes the condition under test is indistinguishable from a
suite that passes. This is the same class as the "absence-only assertion is not a guard" lesson.

## The fix

**Deleted the block.** Not gated — deleted. Two candidate gates were rejected **by measurement**:

| Candidate gate | Why it fails |
|---|---|
| `quote.timestamp` is old ⇒ feed frozen | **Measured false.** It returns `13:52:05.876Z` against a clock of `13:52:06.4` — it is the bridge's **answer** time, not the last trade time. A frozen quote is indistinguishable from a live one. *A name is a claim: read the writer.* |
| Write only when the bridge has a bar in the current bucket | **Identical to deleting it.** If the feed has a current bar, the main loop already wrote it with real OHLCV. If it does not, there is nothing to place a placeholder for. |

Deleting also removes a second, quieter harm: the block ran **last**, so on an open market it
overwrote a real forming bar's `close` with a quote **mid** and widened its high/low.

**Guard:** `nest/src/modules/market-data/bar-refresh-no-synthetic.spec.ts` — 6 cases. Canaried: the
exact synthetic row fails **3 of 6**.

⚠️ **The first canary attempt was INERT and this is worth recording.** It inlined the literals, so the
`$executeRaw` mock recorded **one** value instead of nine and checked `undefined` against the signature
— and the suite went green, which would have read as *"the guard cannot fail"*. Every field must be
interpolated for the canary to land. The spec now carries a positive control so the detector is proven
able to fail independently of the service.

**Data repaired:** the 1,172 provably-fabricated rows deleted. Verified — `0` remain, and XAUUSD 5m
newest is now `2026-10-02 20:50, close 4139.36, volume 623` — **byte-identical to what the bridge
served**.

## Not done — handed on

- **55,518 rows carry the same signature but sit BEFORE Friday's close.** They are almost certainly
  the same writer (it arrived in `b2867f7 "Massive Update"` with no issue and no rationale), but that
  is an *indication*, not a proof — the market was open, so "no bar can exist" does not apply. Deleting
  9% of `marketbar` on an indication is not a decision to take silently. **Owner: this issue.**
  Next step: establish the writer's first-ever write time and compare row counts against intervals the
  market was closed, which converts the indication into a measurement.
- **The staleness implication.** With fabrication removed, a symbol with a genuinely closed market now
  reads as stale — which is *correct*, but `checkDataStaleness()` does not yet know about expected
  market closure and will treat a weekend as a fault. That is a separate, smaller change.
