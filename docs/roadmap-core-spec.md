# Roadmap Core — Data Contract & Interaction Spec

**Issue:** #681 [Epic] Dynamic Roadmap — reusable planning core (kanban × gantt hybrid)
**Status:** Phase A deliverable — confirmed with owner 2026-08-31.

## 1. Model

### Column
- `id` — stable slug (e.g. `phase-1` … `phase-4`, `roadmap`, or generated for sprints)
- `title` — **editable** (the kanban-side customisation)
- `kind` — `phase` | `sprint`
- Default set on first run: Phase 1, Phase 2, Phase 3, Phase 4, Roadmap.

### Card
One card = one GitHub issue (epics render as expandable groups). Local state extends the
build-time snapshot:

| Field | Type | Source |
|---|---|---|
| `number` | int | GitHub (PK) |
| `title` | string | GitHub |
| `state` | open/closed | GitHub |
| `labels` | string[] | GitHub |
| `assignee` | string \| null | GitHub (owner agent) |
| `createdAt` / `updatedAt` / `closedAt` | ISO | GitHub |
| `comments` | int | GitHub |
| `columnId` | string | local DB (derived from phase label on first sync) |
| `position` | DECIMAL(20,6) | local DB |
| `ownerAgent` | string \| null | local DB (initialised from assignee) |
| `blockedBy` | int[] | local DB (issue numbers) |

## 2. Ordering — fractional indexing (decision 8)

- Inserting between neighbours A and B: `position = (A + B) / 2`, rounded to 6dp.
- Inserting at the top: `first − 1`; at the bottom: `last + 1`.
- Gap exhausted (`next − prev < 1e-6`): rebalance that column at integer steps
  (`1.00, 2.00, …`) — a local pass, never global re-numbering.
- Sorting is `ORDER BY columnId, position` — no comparator tricks needed.

## 3. Dependencies (decision 9)

- **Within a column:** top-to-bottom order IS the sequence; a card above is the
  blocker of everything below it.
- **Across columns:** explicit `blockedBy` references (issue numbers).
- **Enforcement:** the board refuses to drop a card above any of its blockers
  (with a visible reason); blocked cards render a small chain badge.
- **Rendering:** dependency edges as connector lines between cards, following the
  meta-stack-pipeline lane language.

## 5. API — NestJS `roadmap` module (interactive state only)

No GitHub client server-side. Prisma model `RoadmapCard`:

```prisma
model RoadmapCard {
  number     Int      @id
  columnId   String   @db.VarChar(40)
  position   Decimal  @db.Decimal(20,6)
  ownerAgent String?  @db.VarChar(50)
  blockedBy  Json
  updatedAt  DateTime @updatedAt
}
```

| Endpoint | Purpose |
|---|---|
| `GET /api/roadmap` | snapshot ∪ local state (single merged payload) |
| `POST /api/roadmap/cards/:number/move` | `{ columnId, position }` (UI computes midpoint) |
| `POST /api/roadmap/cards/:number/owner` | `{ agent }` |
| `POST /api/roadmap/cards/:number/deps` | `{ blockedBy }` |
| `POST /api/roadmap/columns` / `PATCH /api/roadmap/columns/:id` | sprints & title edits |

Move validation happens server-side too (dependency order), not just in the UI.

## 6. Layering — the portable core

- **Core (portable, pure):** `src/core/roadmap/` — fractional position math,
  dependency validation, types. Unit-tested, zero TCS imports.
- **Rendering (portable):** `src/components/roadmap/` — `RoadmapBoard`,
  columns, cards — theme tokens only (`--panel/--line/--ink/--accent`),
  HTML5 drag-and-drop with midpoint drop targets, dependency enforcement
  via `validateMove`, cross-column dependency edges (SVG overlay).
- **Config (TCS adapter):** `src/core/roadmap/roadmap-config.js` — label → column
  mapping, issue → page links, column defaults. Future projects supply their own
  config file; nothing else changes.
